# 训练和诊断边界

## 配方

`scripts/train.py` 包装原始 `go2_arm/train_duet.py`。默认参数与导出时 v11 正式试训一致：4096 环境、阶段预算 40000 + 40000、有界运行 20000 更新，最终文件为 `model_19999.pt`。运行目录拒绝复用，当前恢复 CLI 未验证并主动拒绝。

监督脚本按新运行的实际 PID 与启动 ticks 管理探针。1000 / 3000 时分别执行 stop、前后 ±0.26、左右 ±0.23 的 10 项 style 测试；9000 时执行 90 项完整固定指令测试。每个计划点另执行种子 61119 的 18 项停车 / 再起步测试，3000 另加种子 61120。训练成功结束后，验证最终检查点，再执行完整方向测试与两个种子的停车测试。

训练 `manifest.json` 保存全部 Python 与物理资产哈希；`progress.json`、`train.exitcode`、`result.json` 和检查点必须一起判断。`health_failure.json` 表示健康保护触发，须先保留证据。

## 日志统计范围

- `progress.metrics` 仅最近复位批次；不能冒充全部 4096 环境或 20 分钟汇总。
- `style_positive_factor_mean` 为该次更新末帧的环境均值。
- `rollout_health` 汇总该次更新的全部复位。20 分钟趋势只比较覆盖充分且指令混合、姿态范围匹配的窗口。
- 成功 EMA / 六方向门槛是训练信号，不能替代独立固定指令测试和整机验收。

静止诊断观察门槛为：停车 2 秒后的四脚同时接触 ≥95%、各脚接触 ≥98%、足底离地 P95 ≤1cm、各脚平均法向载荷份额 ≥12%。这不是最终用户精度目标的放宽。

原始 `stop_transition_probe.py` 的 settle 估计按 25 帧减去 0.50 秒，存在一个采样间隔偏差。保留原工具以匹配已运行协议；使用 `scripts/analyze_settle.py` 对原始轨迹按实际连续满 0.50 秒重算，原始结果不覆盖。

## 导出时已知结果

v11 model3000，零姿态参考、PhysX CPU 自由底盘、完整载荷：

- 种子61119：18/18过渡无物理终止，36/36静止段、32/32运动段响应通过。
- 种子61120：17/18过渡完成，35/36静止段通过，1段因终止缺失；32/32运动段响应通过。
- 剩余失败是采样策略从 +1m/s 再次停车后的物理终止。原轨迹缺细分碰撞 / 低机身 / 头部标志，不能臆断原因。
- 低速固定指令完整周期约2.21–2.37Hz，仍高于低速设计带。

这些是早期检查点的有限工况诊断，不能称整个任务完成。前代 v10b 因用户要求修复而有意停止，不是自发崩溃。

## 最终目标仍待验证

速度 / 转速 RMSE ≤0.10；姿态 ≤3°；机械臂各关节 RMSE ≤0.5° / P95 ≤1°；TCP 位置 RMSE ≤1cm / P95 ≤2cm，姿态 RMSE ≤2° / P95 ≤3°；超调 ≤0.1°；静止关节峰峰 ≤0.05° / 末端 ≤0.5mm。

实际 P95、静止峰峰、模式切换和 stage2 整机验收未完成。固定底盘机械臂检查和只观察“不摔倒”均不能替代整机验收。
